# 微信支付页面无障碍读取验证

日期：2026-11-10（Asia/Singapore）。设备：iQOO 13，Android 16 / API 36；微信 8.0.80。

## 结论

在该设备、该版本微信和当前系统配置下，普通第三方无障碍服务无法从微信支付消息列表及单笔交易详情页取得可读文字节点。两种页面均在屏幕上正常显示，但接口返回一个空根节点。此结论仅适用于本次实测环境；未定位具体限制来自微信还是系统，不能据此断言所有微信版本或安卓手机都如此。

用户授权范围为先验证、可读时再接入。由于可读条件不成立，未向 PayWhy 正式应用加入无障碍权限或采集服务；现有通知采集与邮件功能保持原版本。

## 验证方法与结果

1. 先在用户打开的微信支付消息页面使用 UIAutomator 检查，返回单个空节点。
2. 构建、安装独立临时程序 `io.github.yufeisun5.paywhy.probe`，通过系统设置正常启用其无障碍服务。
3. 服务声明 `canRetrieveWindowContent`，订阅窗口／内容变化／滚动事件，启用视图 ID、非重要节点及交互窗口访问。未声明为辅助残障用户的 accessibility tool，未申请网络、输入控制或截图能力。
4. 从 `AccessibilityService.getRootInActiveWindow()` 直接读取，在 UIAutomator 未连接期间验证消息列表和交易详情。
5. 使用同一服务读取临时程序自己的合成页面作正向对照，排除“服务没有运行或完全没有读取权限”。

| 页面 | 节点数 | 有文字或描述的节点 | 金额节点 | 可见节点 |
|---|---:|---:|---:|---:|
| 微信支付消息列表 | 1 | 0 | 0 | 0 |
| 单笔交易详情 | 1 | 0 | 0 | 0 |
| 临时程序合成对照页面 | 7 | 3 | 1 | 7 |

微信窗口事件能够到达服务，根节点的边界为空。服务诊断仅保存节点数量、类型、字符串长度、固定字段标签及金额是否存在，不保存支付原文。合成对照页使用测试金额，不是交易记录。

## 清理与后续

验证完成后已卸载临时程序，确认其无障碍服务不再启用；删除手机上的临时 UI XML 及 Mac 上仅用于人工定位页面的临时截图／XML。仓库不保存真实支付截图、商户、金额、订单号、银行卡信息或无障碍原文。

通知栏中不存在的支付消息，不能依赖通知监听采集；常驻前台服务不改变此限制。若继续开发其他入口，可独立评估用户主动分享支付详情截图后的本地 OCR，或账单导入。它们尚未实现，也不应描述成已经支持完全自动获取微信流水。

接口依据：[Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[无障碍服务配置](https://developer.android.com/guide/topics/ui/accessibility/views/service)。
